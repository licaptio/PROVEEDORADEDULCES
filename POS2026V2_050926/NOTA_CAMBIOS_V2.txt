PROVSOFT POSPDD26 - VERSION 2026.2

CAMBIOS PRINCIPALES

1. Ruta, caja y usuario dinamicos
- Ventas, ventas en espera, reimpresion y cortes se identifican por el usuario logueado.
- La caja deja de guardarse y de usarse como filtro.

V8
- El campo principal sirve para escanear códigos exactos y buscar productos por texto.
- Si no existe un código exacto, abre el modal de búsqueda con el texto capturado.
- Se eliminó el botón separado "Buscar por concepto".

V9
- Al abrir Cobro primero exige seleccionar Efectivo, Tarjeta, Transferencia o Pago mixto.
- Efectivo permite capturar el importe recibido y calcular el cambio.
- Tarjeta y Transferencia cargan automáticamente el total exacto.
- Pago mixto muestra Efectivo 1, Efectivo 2, Tarjeta y Transferencia.

V10
- Cancelar una captura limpia inmediatamente el respaldo automático local.
- Si la venta fue recuperada, se cancela el documento original en lugar de duplicarlo.
- El modal de ventas en espera excluye ventas canceladas, eliminadas o cobradas.
- Cada venta en espera incluye Cancelar con contraseña y motivo para limpiar registros anteriores.

V11
- El motivo de cancelación ya no se escribe manualmente.
- Se muestran únicamente cinco motivos seleccionables definidos por operación.
- Firebase guarda el texto y el código normalizado del motivo seleccionado.

V12
- La búsqueda por descripción abre automáticamente el modal después de escribir dos letras.
- Ya no es necesario presionar Enter para buscar por nombre o concepto.
- Los códigos numéricos esperan el Enter del escáner y se agregan directamente.
- Se retiró el contenedor antiguo de resultados que permanecía oculto y ya no se utilizaba.

V13
- La búsqueda es multicoincidente: exige que aparezcan todas las palabras capturadas.
- El orden de las palabras no importa.
- Formatos compactos como C6 también coinciden con C/6.

2. Cobro y pago mixto
- Efectivo 1
- Efectivo 2
- Tarjeta
- Transferencia
- Total de pagos, faltante y cambio.
- La venta guarda metodo_pago y arreglo pagos.

3. Corte
- Desglose por Efectivo 1, Efectivo 2, Tarjeta y Transferencia.
- Efectivo a entregar excluye tarjeta y transferencia.
- Conserva usuario, ruta y caja del usuario conectado.

4. IndexedDB
- Cola offline, sesion, folios, venta interrumpida, venta recuperada y configuracion local.
- Migracion automatica de los datos anteriores de localStorage.
- La venta se guarda localmente antes de imprimir y se elimina cuando Firestore confirma.

5. Catalogo incremental
- Muestra inmediatamente IndexedDB.
- Consulta solamente documentos con updatedAt posterior a la ultima sincronizacion.
- Usa el Timestamp real updatedAt; actualizadoEn se conserva como dato auxiliar.
- Reconoce codigoBarra, codigosEquivalentes, activo, costoSinImpuesto y demas campos reales.

6. Fotografias
- Las fotos locales aparecen de inmediato.
- La actualizacion remota ocurre en segundo plano y no bloquea la entrada al POS.

FIRESTORE
- La region nam5 no requiere cambio en el codigo web; pertenece al proyecto Firestore.
- Cada producto debe conservar updatedAt como Timestamp de Firestore.
- Para detectar bajas, el producto debe actualizar updatedAt al cambiar activo a false.
- productos_fotos_meta debe usar updatedAt Timestamp para sincronizacion incremental.

CONFIGURACION MANUAL
- Colocar las credenciales web reales en js/firebase/config.js.

7. Indicador ONLINE / OFFLINE
- Se muestra en la parte inferior derecha del POS.
- Verde animado: internet y Firebase respondieron correctamente.
- Rojo animado: sin internet o sin comunicacion con Firebase.
- Amarillo animado: verificando conexion.
- Reacciona inmediatamente a los eventos online/offline del equipo.
- Confirma Firebase al abrir y cada cinco minutos para economizar lecturas.

8. Arranque protegido V4
- Pantalla bloqueadora animada antes del login.
- Prepara IndexedDB, catalogo local y actualizacion incremental.
- Verifica que existan productos activos antes de mostrar usuario y contraseña.
- Primera instalacion sin catalogo y sin Firebase: bloquea y permite reintentar.
- Con catalogo local y sin Firebase: permite continuar offline con advertencia.
- Las fotografias locales se preparan antes del login; la descarga remota sigue en segundo plano.
- Muestra cantidades de productos, cambios descargados y fotografias locales.

9. Ruta central de ventas V5
- Todas las ventas reales de usuarios se guardan en:
  CLIENTES/PDD031204KL5/VENTASV20261/{id_venta}
- Ventas en espera, recuperacion, cancelacion, cola offline, reimpresion y corte
  consultan y actualizan la misma coleccion.
- Usuario, ruta y caja se conservan como campos dentro de cada documento.
- Solo un usuario marcado expresamente con venta_prueba=true utiliza VENTASPRUEBAS.

10. Menu visible y recuperacion V6
- El boton de tres puntos queda fijo en la esquina superior derecha.
- Los datos largos de usuario, ruta o folio ya no pueden sacar el menu de pantalla.
- El menu conserva la opcion Recuperar Venta.
- Atajo F7 abre directamente Recuperar Venta.
- F8 conserva Mandar a Espera y F9 conserva Cobrar.

11. Encabezado limpio V7
- Se elimina el titulo Proveedora de Dulces del encabezado operativo.
- Se ocultan Ruta, Caja y Cliente.
- Solo se muestran Usuario y Folio.
- El boton de tres puntos permanece fijo y visible.
